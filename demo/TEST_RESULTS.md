## 前次版本的独立复核与 100 球性能（历史记录）

独立脚本检查了 320×568、360×640、390×844、768×1024 实际窗口尺寸转换后的九个按钮和场地边界，均在视口内。按钮实际高度约 44.4 / 50 / 54.2 / 91.4 像素。320×480 约 42.9 像素、844×390 横屏约 34.8 像素，因此不把窄矮窗口或横屏称作足够触摸尺寸；Android 预设保持竖屏。

独立鼠标命中与合成 `InputEventScreenTouch` 能正确选择 2 / 5 球；五种数量和强制错误面板未超出布局。Android safe-area 逻辑和关闭 edge-to-edge 的配置存在，但没有在设备上验证刘海/系统栏表现。

seed 7 / 42 / 99 的独立 100 球测试各运行 120 步：

- 每 1 秒模拟约用 **8.39–9.34 秒**墙钟时间。
- 单步 p50 约 69.8–77.8 ms，p95 约 116.6–141.3 ms，最高约 183.9 ms。
- 运行后的实际 2× 渲染回调各测 20 次：p50 约 69.9–103.6 ms，最高约 224.7 ms；每回调通常只完成一个固定步，之后丢弃积压。
- 回调结束后的 100→1 切换约 0.41 ms。
- 无求解错误；相对能量漂移不超过约 3.04e-8。

**12 ms 是步间调度预算，不是单步、帧时或输入延迟上限。** 本机 100 球明显不能实时，更不能保证手机实时或 2× 实际速度。没有为提高表面帧率而改动物理步长、球半径、速度或碰撞模型。上述短时测试不是任意种子、任意时长的稳定性保证。

已有 `Android` 预设，包名 `org.gankkiii.ballsdemo`，ARM64 + ARMv7，普通 APK，禁用 immersive/edge-to-edge，不申请网络权限。README 给出了 `--path demo` 导出与调试安装流程。SDK 路径、签名密码、密钥和生成 APK 不在仓库中。

实际尝试 `godot --headless --path demo --export-debug Android build/balls-demo.apk` 被环境缺项阻挡，导出器明确报告：

- 找不到 Godot 4.6.3 的 `android_debug.apk` / `android_release.apk` 导出模板。
- 没有有效完整 Java SDK 路径；当前只有 Java 21 runtime，未发现 `javac` / `jarsigner`。
- 没有有效 Android SDK、platform-tools / `adb`、build-tools / `apksigner`。

**没有生成或验证 APK，没有运行 Android 模拟器、连接手机、打包安装或真机测试。** 预设被识别不等于 APK 构建通过，需要按 README 补齐匹配工具链后再次导出。
