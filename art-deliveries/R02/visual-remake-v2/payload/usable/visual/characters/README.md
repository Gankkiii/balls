# R02 角色与道具：本轮重制原件

版本 `R02-remake-characters-1`。这是用户确认“兔、鸭及道具全部重制”后的新作品，不是找回的旧 R02 源文件，也不是裁切评审图或视频得到的素材。只制作资源与说明，未修改游戏脚本、场景、玩法或团队配置。

## 可直接导入文件

- `duck/default.png`、`rabbit/default.png`：透明默认图。
- `duck/{idle,cast,impact,recover}/frame_00.png` 等：对应动作的透明独立帧。
- `rabbit/{idle,forge,temper,hit_recover}/frame_00.png` 等：对应动作的透明独立帧。
- 同角色目录的 `*_strip.png`：横向帧条，左到右，无空格，每格96×96。
- `props/broad_blade.png`、`forge_hammer.png`、`anvil.png`、`lightning_rod.png`：独立宽刀、锻造小锤、铁砧、避雷针。不是新增碰撞体或障碍物。
- `character_manifest.json`：逐帧路径、时长、循环方式、透明包围盒、独立画面数、事件帧、SHA-256。

全部角色帧与道具为96×96 RGBA；底层48×48整数像素几何，以nearest放大2倍。透明alpha只有0/255，不含背景和抗锯齿半透明边缘。A风格的深蓝灰轮廓、暖黄鸭/珊瑚帽、淡紫长耳兔/围裙、浅青宽阶梯刃与紫中脊沿用既有设定。宽刀、锻造锤作用严格分开。

本轮使用96画布代替旧册声明但未找到原件的64画布，仅为耳朵和横向宽刀留足透明空间；不是扩大角色碰撞半径。主体身体原点 `(48,56)`，脚底锚点 `(48,80)`。挂在物理身体节点时，应将Sprite位置设成 `(-48,-56)`，对应脚底在身体原点下24像素；若采用Sprite2D centered=true，其节点位置应为 `(0,-8)`（96图像中心是48/48）。这只是本批新素材技术坐标，未在真实游戏中验收。

主朝右；左向可镜像。连续边界坐标镜像 `x'=96-x`，像素索引为 `x'=95-x`，不可混用。中心线身体/脚底锚点镜像后保持不变。全动作身体原点和脚底基准不变，呼吸只改变躯干/头部，脚底不作世界运动。

## 动作与触发

|动作|帧数/时长ms|循环|接入语义|
|---|---|---|---|
|duck idle|4×160|是|轻呼吸与翅膀变化|
|duck cast|100/100/120/160|否|现有鸭技能事件后的局部抬翅/电火花反馈，不新增技能或手持武器|
|duck impact|70/80/100/120|否|鸭实际受到有效伤害后的轻压缩/表情反馈|
|duck recover|100/120/120/160|否|受击后回到idle的短恢复；不改变速度或免伤状态|
|rabbit idle|4×160|是|持宽刀就绪，4逻辑格有3个不同画面，回环重复如实保留|
|rabbit forge|160/100/80/90/110/160|是，仅forge期间|宽刀横置铁砧，小锤抬起→接触→回收；**index2**为接砧声`anvil_forge.wav`。整段700ms不决定真实2秒锻造时长|
|rabbit temper|4×140|是，仅temper_left>0|持宽刀淬炼局部高光，不额外制造攻击|
|rabbit hit_recover|70/80/110/160|否|**index0已经是接触命中姿势**，其后为回收至就绪；真实碰撞/伤害当帧触发，不排前摇、不延迟`hit()`|

全批共34张独立角色帧、8张strip、2张默认图、4张独立道具。除了rabbit idle的回环重复，其余7动作每格画面不同；不同画面数不代表独立自动用例数。所有像素包围盒见manifest，hit宽刀尖端最右到x=94（不含界），距96画布右边保留2px透明余量。

图层建议：角色动作内已经画入手持刀/锻造工具和当前锻造砧；使用完整角色帧时不要再叠一把同款刀或第二个砧。独立道具供需要拆层或单独表现的实现使用，不代表必须与整帧重复叠加。地面避雷针依真实`rods`位置放置，画面尺寸不等于半径100保护范围。

1×/2×/3×动画随模拟时间，暂停冻结帧与事件；重开/死亡/切场清理本角色表现状态。有效命中声用`sword_wide_hit.wav`，锻造声用`anvil_forge.wav`，不把旧短剑声或锤战斗声配给宽刀。音效仍引用现有7WAV，不在本目录重新合成。

## 制作源与复现

`source/build_characters.py` 是本轮原创制作源，直接描述全部像素几何/姿势/调色板，不读取任何旧图片。依赖Python3与Pillow，运行：

```sh
python3 source/build_characters.py --output /path/to/new-directory
```

请在新目录复现、比对哈希，不覆盖已审核包。`source/svg/` 是逐帧与道具的可编辑SVG导出；按水平像素色段表示，可无损改色，96×96下alpha及非透明像素应与PNG一致。Inkscape等渲染器可能在alpha=0的完全透明像素下写入不同隐藏RGB，不影响透明显示；不据此改动导入PNG。动作姿势的结构性编辑优先修改Python源，再重新导出。预览标签优先使用系统DejaVu Sans，若不可用则回退Pillow默认字体；角色/道具资产自身不含文字或字体依赖。

`../../../../reference/previews/characters/` 只用于审核：整张对照、3×nearest大图和带帧序/时长的动作总览。它们是从本轮自制原件生成的展示，不是游戏截图，更不是独立帧素材的来源。

未验证：真实游戏内渲染/事件绑定/锚点/左右翻转观感/手机尺寸/音画听感。素材文件读取、透明边界、源复现和图像规格的实际检查由交付QA另记，不能据此宣称已接入游戏或真机通过。


交付打包说明：本轮审核预览已单独归档至包根 `reference/previews/characters/`；它们是实际原件的组合展示，不是游戏实录，也不是可导入组件。制作源在新输出目录重建时会生成其自己的 `preview/`。
